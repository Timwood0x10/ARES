## 🔍 真实缺口分析

### 缺口 1: Kernel 集成层（P1 - 阻塞多 Agent 协作）

**现状**: `taskfabric.Fabric` 和 `agentfabric.Fabric` 是独立的，缺乏统一的调度入口。

**问题**: 
- Agent 如何知道哪些 Task 可用？
- Agent 如何通过 IPC 与其他 Agent 协作？
- Scheduler 如何协调多个 Fabric？

**设计原文**: *"Kernel 管'能不能、怎么活、怎么跑'；Agent 管'我要做什么、要不要生孩子、怎么协作'。"*

**需要新增**:
```go
// internal/runtime/kernel.go (缺失)
type Kernel struct {
    taskFabric   *taskfabric.Fabric
    agentFabric  *agentfabric.Fabric
    ipcBus       *agentipc.Bus
}

func (k *Kernel) RunQuantum(ctx context.Context, agentID string) error {
    // 1. Agent 向 Kernel yield 执行权
    // 2. Kernel 检查是否有新 Task 可 acquire
    // 3. Kernel 检查是否有 IPC 消息待处理
    // 4. Kernel 决定下一步：continue/suspend/preempt/handoff
}
```

### 缺口 2: Event 驱动的 Agent 循环（P1 - 兑现设计愿景的关键）

**现状**: `leader/agent.go` 是命令式调用，不是事件驱动。

**问题**: 
- Agent 如何响应 Task 分配事件？
- Agent 如何响应 IPC 消息事件？
- Agent 如何响应进化事件？

**设计原文**: *"Agents are not orchestrated. They are scheduled."*

**需要新增**:
```go
// internal/agentloop/engine.go (部分实现，需增强)
type Engine struct {
    kernel   *Kernel
    eventBus *ares_events.EventBus
}

func (e *Engine) Run(ctx context.Context) error {
    // 事件循环：
    // - TaskAcquired → Start execution
    // - TaskYielded → Check for more work
    // - IPCMessageReceived → Handle message
    // - EvolutionTriggered → Update strategy
}
```

### 缺口 3: Multi-Agent 协作模式（P2 - 高级特性）

**现状**: 单个 Agent 可以 spawn 子 Agent，但缺乏协作模式。

**建议新增协作原语**:
```go
// internal/agentipc/collaboration.go (缺失)
type CollaborationMode int

const (
    ModeDelegation CollaborationMode = iota  // A 委托 B 完成任务
    ModePipeline                              // A → B → C 流水线
    ModeOrchestration                         // A 协调 B、C 并行
    ModeConsensus                             // A、B、C 投票决策
)

func (b *Bus) Collaborate(ctx context.Context, mode CollaborationMode, 
    participants []string, taskID string) error
```

## 结论

ares-runtime.md 的核心设计（Task Fabric + Agent Fabric + IPC）**已经大部分实现**。

**真正的缺口**在于：
1. **Kernel 集成层** - 缺少统一调度入口
2. **Event 驱动 Agent 循环** - 现有 Agent 是命令式调用，非事件驱动
3. **Multi-Agent 协作模式** - 缺少高级协作原语
4. **资源隔离 enforcement** - 有 quota 声明，无实际限制

建议 v0.4.0 聚焦于 **M1 + M2**（Kernel 集成 + Event 驱动循环），这是兑现 *"Agents are not orchestrated. They are scheduled."* 设计愿景的关键。
