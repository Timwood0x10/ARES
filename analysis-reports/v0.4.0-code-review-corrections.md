## 🔴 正确性问题

### Bug 1: Recovery 替换的 Agent 无法执行任务

**位置**: `internal/aresrecovery/recovery.go:138`
```go
func (r *Recovery) RecoverTaskCheckpoint(ctx context.Context, taskID, replacementID string) (string, uint64, error) {
    // Spawn replacement agent
    spawned, err := r.spawnAgent(ctx, agentfabric.SpawnSpec{...})
    
    // Acquire task for replacement
    epoch, err := r.tasks.Acquire(taskID, agentID, time.Minute)
    
    // ❌ PROBLEM: spawned agent is NOT registered in kernelScheduler.executors!
    // The scheduler only knows about agents in kernel.executors map
    // This new agent cannot be picked up by the scheduler
}
```

**后果**:
1. Task 被 Acquire 为 LEASED 状态
2. 新 spawn 的 agent 不在 executors map 中
3. 无人能 Execute 这个任务
4. 任务阻塞最多 1 分钟直到 lease 过期
5. Lease 过期后 requeue 回 READY
6. 此时由原来的 executor 池执行（如果还在）

**这是一个半吊子的恢复链**，checkpoint resume 只是象征性的。

### Bug 2: RetryPolicy 语义错误

**位置**: `cmd/ares/kernel.go:141`
```go
RetryPolicy: taskfabric.RetryPolicy{MaxRetries: 1},
```

**CanRetry 逻辑** (`internal/taskfabric/fabric.go:248`):
```go
func (t *Task) CanRetry() bool {
    return t.RetryPolicy.MaxRetries <= 0 || t.RetryPolicy.Attempts < t.RetryPolicy.MaxRetries
}
```

**分析**:
- MaxRetries = 1
- 第一次执行: Attempts=0, 0 < 1 = true → 可以重试？
- 等等，重新看逻辑...

```go
// fabric.go:247-258
t.RetryPolicy.Attempts++  // Attempts 变成 1
if t.CanRetry() {         // 1 < 1? false!
    // requeue
} else {
    // FAILED
}
```

**实际行为**: 
- MaxRetries=1 意味着 0 次重试
- 第一次失败后直接 FAILED
- 这与代码注释"1次重试"矛盾
- 如果想保留1次重试，应该写 `MaxRetries: 2`

**影响**: 任何瞬时失败都变成终局失败，没有容错能力。

### Bug 3: Yield 后 Resume 丢失 UserProfile

**位置**: `cmd/ares/kernel.go:147-153`
```go
Checkpoint: fabricTaskMeta{
    UserProfile:      task.UserProfile,      // ← 保存时
    Payload:          task.Payload,
    UsedExperienceID: task.UsedExperienceID,
},
```

**问题场景**:
1. submitFabricTask 将 fabricTaskMeta 放入 Checkpoint
2. quantum 执行 Yield → checkpoint 被替换为普通 map
3. toModelTask 尝试恢复 UserProfile:
```go
if meta, ok := tk.Checkpoint.(fabricTaskMeta); ok {
    t.UserProfile = meta.UserProfile  // ← type assertion 失败！
}
```
4. UserProfile = nil
5. Executor 退化为 executeByType 空结果

**当前未触发原因**: 生产环境中 quantum 恒返回 done=true，不走 Yield 路径。
**潜在风险**: 一旦有长任务需要 yield-resume，UserProfile 丢失导致退化执行。
