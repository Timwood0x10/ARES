## 🔴 Critical Issues Found

### C1: Spinning Loop Risk in runKernelQuotaLoop

**File**: `cmd/ares/kernel.go:402`
```go
func runKernelQuotaLoop(ctx context.Context, mgr *aresrecovery.EvolutionAwareQuotaManager) {
    if mgr == nil {
        return
    }
    apply := func(phase string) {
        if err := mgr.Apply(ctx); err != nil {
            log.Printf("kernel: quota apply (%s): %v", phase, err)
        }
    }
    apply("startup")
    ticker := time.NewTicker(quotaApplyInterval)  // 1 minute
    defer ticker.Stop()
    for {
        select {
        case <-ticker.C:
            apply("tick")
        case <-ctx.Done():
            return
        }
    }
}
```

**Issue**: If `mgr.Apply(ctx)` blocks or panics, the loop will spin forever (ticker keeps firing).

**Fix**: Add timeout to Apply call:
```go
apply := func(phase string) {
    ctxWithTimeout, cancel := context.WithTimeout(ctx, 30*time.Second)
    defer cancel()
    if err := mgr.Apply(ctxWithTimeout); err != nil {
        log.Printf("kernel: quota apply (%s): %v", phase, err)
    }
}
```

### C2: Potential Goroutine Leak in subscribeResults

**File**: `cmd/ares/kernel.go:786`
```go
func (d *kernelTaskDispatcher) subscribeResults(ctx context.Context) (<-chan *ares_events.Event, error) {
    if d.store == nil || d.fabric == nil {
        return nil, errNoResultSubscription
    }
    return d.store.Subscribe(ctx, ares_events.EventFilter{...})
}
```

**Issue**: The channel returned is never closed explicitly. If the store's internal subscription fails silently, the goroutine in Dispatch() will leak waiting on `<-resultCh`.

**Fix**: Add proper cancellation handling:
```go
ch, err := d.store.Subscribe(ctx, filter)
if err != nil {
    return nil, err
}
// Wrap channel to handle errors
go func() {
    defer close(ch)
    for ev := range ch {
        select {
        case resultCh <- ev:
        case <-ctx.Done():
            return
        }
    }
}()
```

### C3: Missing Timeout on Recovery Loop

**File**: `cmd/ares/kernel.go:517`
```go
func runKernelRecoveryLoop(ctx context.Context, store ares_events.EventStore, recovery *aresrecovery.Recovery) {
    // ... subscription setup ...
    
    ticker := time.NewTicker(recoverySweepInterval)  // 1 second
    defer ticker.Stop()
    for {
        select {
        case <-ctx.Done():
            return
        case <-ticker.C:
            recovery.RecoverFromAgentDeath(ctx)  // ← No timeout!
        case _, ok := <-events:
            if !ok {
                return
            }
            recovery.RecoverFromAgentDeath(ctx)  // ← No timeout!
        }
    }
}
```

**Issue**: If `RecoverFromAgentDeath(ctx)` blocks indefinitely (e.g., due to database hang), the entire recovery loop freezes.

**Fix**: Add timeout:
```go
case <-ticker.C:
    ctxWithTimeout, cancel := context.WithTimeout(ctx, 5*time.Second)
    go func() {
        defer cancel()
        recovery.RecoverFromAgentDeath(ctxWithTimeout)
    }()
```

## 🟡 Low Priority Issues

### L1: No Graceful Shutdown for Spin Loops

All three kernel loops (quota, trace, recovery) run as goroutines but have no graceful shutdown mechanism other than ctx cancellation. If the parent context is cancelled, these loops will exit, but any in-progress operations (Apply, Trace, Recover) may be aborted mid-execution.

**Recommendation**: Add shutdown hooks:
```go
func runKernelQuotaLoop(ctx context.Context, mgr ...) {
    // ...
    go func() {
        <-shutdownChan
        mgr.Shutdown()  // Graceful shutdown
    }()
}
```
