## 观察 3：错误处理 — ✅ 已处理

**问题**：`createLLMAdapterWithFallback` 失败时返回 `fmt.Errorf("no LLM adapter available: %w", err)`，
无错误码，无法 `errors.Is` 检测。

**处理**：

- 新增测试 `TestErrNoLLMAdapterSentinel`：验证 sentinel 可检测、底层错误保留、
  sentinel 与普通错误身份隔离。

## 观察 4：并发安全 — ✅ 已核实，现状安全

**问题**：担心 `runtime.Manager` 注册表 `map[string]*Agent` 无锁，动态注册/注销会 panic。

**核实**：`internal/ares_runtime/manager.go:42-43`——
```go
mu     sync.RWMutex
agents map[string]*managedAgent
```
`Manager.mu`（RWMutex）已保护 `agents`/`factories`/`chaosConfig`/`dagStore` 全部 map；
所有读写路径（`RegisterAgent`/`StartAgent`/`StopAgent`/`NotifyAgentDead`/`RestoreAgent`/
`healthCheck`）均在锁内。现有测试 `TestManager_ConcurrentNotifyAgentDead`、
`TestManager_Stop_ConcurrentStopAgent` 已覆盖并发路径（含 `-race`）。

**结论**：观察不成立，无需处理。新增动态注册/注销时保持 `m.mu` 约定即可。

## 观察 5：测试覆盖 — ✅ 已处理（补健康检查）

**问题**：健康检查、热更新、resource quota 等核心功能未覆盖。

**核实**：
- recovery/quota 已有测试：`internal/aresrecovery/recovery_test.go`（恢复链）、
  `evolution_quota_test.go`（配额）、`internal/agentfabric/resource_test.go`（资源预算）。
- **缺口**：`runtime.Manager.healthCheck()`（manager_lifecycle.go:349）无直接测试——
  后台健康轮询检测到死 agent 并触发复活（resurrection）的路径未覆盖。

**处理**（补两个测试于 `internal/ares_runtime/runtime_test.go`）：
- `TestManager_HealthCheck_DetectsDeadHeartbeatAndResurrects`：注册 `Heartbeater`
  且 `IsAlive()==false` 的 agent → `healthCheck()` 检测到心跳失败 →
  `NotifyAgentDead` → factory 复活。用轮询等待，避免时序误判。
- `TestManager_HealthCheck_IgnoresHealthyHeartbeat`：`IsAlive()==true` 的 agent
  不被误杀（不触发复活）。
- 新增 mock：`deadHeartbeatAgent` / `aliveHeartbeatAgent`（均实现
  `base.Heartbeater` 的 `Heartbeat`+`IsAlive` 双方法）。

> 注：实现测试时发现 `base.Heartbeater` 接口需要 `Heartbeat(ctx)` + `IsAlive()` 两个方法，
> 最初只实现 `IsAlive()` 导致类型断言失败——已补齐。健康「热更新」场景（MCP 配置热加载
> fsnotify）已有 `ares_mcp/config_watcher.go` 覆盖，故未重复造。
