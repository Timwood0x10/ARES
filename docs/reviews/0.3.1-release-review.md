## 一、四问直答

### 1. 项目模块是否彻底闭环了？

**核心链路：闭环。边缘模块：未闭环（且有明确登记）。**

| 层 | 状态 | 依据 |
|---|---|---|
| 任务执行主链（submit → fabric → scheduler → quantum → complete） | ✅ 闭环 | Grand-loop e2e：created→acquired→yielded→killed→recovered→completed 全链路断言 |
| 租户链（HTTP → envelope v5 → tenantctx → 仓储谓词） | ✅ 闭环 | 全链测试 + 契约测试 + 17 处 fail-closed |
| 知识环（AKG 检索/蒸馏/进化） | ✅ 闭环（本批补齐） | KnowledgeStore 接口租户化 + store_adapter 两个跨租户漏洞修复 |
| 事件环（append → subscribe → compaction → retention） | ✅ 闭环 | 丢弃日志采样 + goleak 门禁 |
| **evolution（v1 GA）/ v2 双轨** | ⚠ 未闭环 | v2 仅 candidate pipeline 存在，无生产装配；v1 是活的。设计如此（能力储备），但"进化自主闭环"未达成 |
| **peer 通信（agentipc）** | ⚠ 未闭环 | 无 ACL、无重试/死信（F-15，已文档化为单租户 v1 边界） |
| **LLM 流式** | ⚠ 未闭环 | `Agent.Stream` 是"跑完再分块回放"（E-12）；底层 `GenerateStream` 真流式但零生产调用 |

**结论**：作为"任务执行 + 知识 + 记忆"的 agent runtime，主干闭环成立；自主进化和流式是 0.4 方向，不是 0.3.1 的承诺范围。

### 2. 能否发布 0.3.1？

**能，带条件。**

✅ 满足项：
- `make check` exit=0（vet / staticcheck / golangci 0 issues / 129 包全测绿）
- `make gate` exit=0（本次评审修复了 G1 白名单滞后——`postgres/services` 转为 examples-only 未同步，CI 会红灯，已按 D6 先例补白名单）
- CI 含 pgvector + race + closure 门 + 双 Postgres 版本矩阵
- soak 稳态（goroutine/fd/heap 三轴平稳）
- CHANGELOG 0.3.1 段完整（Added/Changed/Security/Fixed/Removed + Known limitations）

⚠ 发布前必须做（人工动作，非代码）：
1. **未提交批次入库**：KnowledgeStore 租户化（工作树 +471/−136）+ 本报告的 gate 白名单修复
2. **版本号落地**：仓库无 `version` 命令/常量，`cmd/ares/doctor` 的 Go 版本白名单只认 go1.25/1.26（C-7：go1.27 误报，若用新工具链构建需先修）
3. **发布说明补两条行为变更**：`WithMaxTokens` 从 no-op 变强制（已写 CHANGELOG）；通配绑定 + 无鉴权现在拒绝启动（容器部署需配置）

### 3. 0.3.1 是否足够稳定？

**对目标场景（单租户部署、认真运维）：是。对多租户：否。**

稳定性证据链：
- 本周期修复约 40 项缺陷，其中 11 项 panic 类（nil 解引用、越界、死锁）全部带锁定测试
- **泄漏三防线**：goleak 门禁（kernel/engine 两包）→ soak 稳态采样 → 每 N-2..N-7/F-17 逐项修复
- **HTTP 三防线**：入口 nil 守卫 sweep → dispatchAction panic 守卫（500+requestID）→ 审计归因（IP/UA/requestID）
- 数据竞争：`-race` 全仓 CI + 本周期修复 3 处真竞争（compactable drain cap、WithMaxTokens 桥接、token 缓存）
- flaky 治理：F-21 根因修复 + 10.03s/10s 类 deadline 全部加 30× 余量 + 未归因 kernel 失败 10 轮 stress 关闭

剩余风险（诚实清单）：
- **`Save` 跨租户改宗开口**（本批 TODO 已登记）：他租户同 ID 行会被覆盖改宗——单租户无害，多租户前必须做 namespace 复合主键（三后端 schema 变更）
- 63 条 backlog（多为 P3/需产品决策），高危项已全部处理或文档化（T-7 code_runner RCE 需外部清单管理）
- 无 PG 支撑的迁移幂等性测试在本地不可跑（CI 有 pgvector 会跑）——本周期两个 boot-breaker 都是这类，CI 是唯一防线，不可绕过

## 三、最终裁定

**0.3.1 可以发布**（条件见 §2），定位为：**单租户、生产可用的 agent runtime**。

- 主干功能闭环、四门全绿、约 40 缺陷修复全部带锁定测试、泄漏/panic/竞争三防线成型
- 多租户**不是** 0.3.1 的发布标准（管道就绪 + Security 文档明示 auth 绑定前提）
- 发布 checklist：① 未提交批次入库 ② doctor 版本白名单确认 ③ release notes 补两条行为变更 ④ CI 观察一轮全绿后打 tag
