# ARES v0.3.0 Release Notes

**Released:** 2026-08-11
**Branch:** dev
**Theme:** Candidate Release Closed-Loop

---

## Overview

v0.3.0 upgrades the evolution system's "selection" from *evaluate* to **layered release gating**: evolution output is wrapped into a stateful, verifiable, releasable **candidate** that flows through `CandidatePipeline`'s full lifecycle — three-gate verification → Release gate → pre-release gate-3 regression confirm → `SetStable`. Gate 3 runs a real-LLM preserved-case regression (`LLMArenaScorer`), and `BatchScorer` merges LLM requests into fewer, larger ones to cope with low-rpm rate limits.

Core idea: **generating candidates is easy; shipping is hard — the release gate decides the safety of the evolution system.** A candidate must prove it does not regress the preserved suite before entering the stable region.

---

## New Features

### 1. Candidate Pipeline (`internal/evolution/`)

```
NewCandidate → Verify (gate1 static + gate2 evidence + gate3 regression) → Verified
             → Release (coordinator decision + canary) → gate-3 confirm → SetStable → Promoted
```

- **`Candidate` + `CandidateStore`** (`candidate.go`): a stateful candidate with lifecycle `candidate → verified → promoted/rejected`; `CandidateStore` is concurrency-safe (`sync.RWMutex`).
- **`CandidateVerifier`**: three gates — Gate 1 static (structure + dangerous-pattern rejection), Gate 2 evidence (referenced failure evidence exists and is `KindDimensionEval`), Gate 3 regression (no preserved-case degradation).
- **`CandidatePipeline`** (`candidate_pipeline.go`): `Release` accepts only `StatusVerified` candidates; coordinator decision → canary → `SetStable` → `Promote`.
- **Release-time gate 3** (`WithReleaseRegressionCheck`): runs **before any patch is built/applied**; on failure the candidate is `Reject` and neither runtime nor stable is touched.
- **Dead-code removal**: removed legacy `promoteToStable`/`applyDiff` (superseded by `CandidatePipeline.Release`), eliminating the dual promotion path.

### 2. Gate-3 LLM Regression

- **`CandidateRegressionChecker`** (`candidate_regression.go`): runs `ares_arena.RegressionTester` comparing `stable.Instructions` vs `candidate.Diff`; rejects on a statistically significant drop (`Confident && NewAvg<OldAvg`).
- **`LLMArenaScorer`** (`internal/ares_evolution/service/llm_arena_scorer.go`): implements `ares_arena.Scorer`, two-step LLM (execute instructions×case → grade output on [0,1]). The grading prompt stays open-ended (anchored rubrics measurably weaken significance).
- **`BuildRegressionGate3` / `LoadRegressionGate3`** (`gate3_orchestrator.go`): top-level assembly; the same check injects into both Verify and Release. `LoadRegressionGate3` loads `llm.Client` from a YAML config, supporting ollama (keyless) / openai (keyed).

### 3. Batch Request Merging (`BatchScorer`)

- **`ares_arena.BatchScorer`** (`regression.go`): optional interface `ScoreBatch(ctx, strategy, count, testCases)`; `RegressionTester.runStrategy` collapses all runs of a strategy into one batch call (falls back to per-run concurrent `Score`, backward compatible).
- **`LLMArenaScorer.ScoreBatch`**: collapses count executions + gradings into exactly **2 LLM calls**. One regression drops from `2×runs` to 2 — critical for low-rpm providers.

### 4. Reliability & Hardening

- `CandidateStore` full `sync.RWMutex`; `TestCandidateStore_ConcurrentAccess` (32 goroutines × 50 submits) passes `go test -race`.
- Gate-2 `replayFailureCases` queries the evidence store, distinguishing missing vs wrong-kind evidence (no fabricated IDs).
- `Verify()` advances the state machine: all gates pass → `StatusVerified`; any failure → `StatusRejected` + reason; nil-candidate guard.

## Breaking Changes

| Change | Before | After |
|--------|--------|-------|
| `CandidateStore.promoteToStable` / `applyDiff` | candidate direct-to-stable | **removed** (use `CandidatePipeline.Release`) |
| `CandidateVerifier` constructor | `NewCandidateVerifier(regressionCheck)` | + `NewCandidateVerifierWithOptions(WithEvidenceStore, WithRegressionCheck)` (old kept) |
| `CandidatePipeline` constructor | `NewCandidatePipeline(...)` | + `NewCandidatePipelineWithOptions(..., opts...)` (old kept) |

## Real-LLM Measurements (provider comparison)

Same preserved suite:

| Provider | Model | Good avg | Bad avg | Verdict |
|----------|-------|----------|---------|---------|
| sensenova | deepseek-v4-flash | 0.85 (single call) | 0.00 | rpm-limited, single call |
| Ollama | gemma4:e2b | 0.20 | 0.00 | weak exec, no significant verdict |
| Ollama | gemma4:e4b | 0.16 | 0.03 | p=0.0051 significant |
| **agnes-ai** | **agnes-2.5-flash** | **0.45** | **0.14** | **p=0.0297 significant + no rpm** |

Full release closed-loop (`examples/18-release-closed-loop`, agnes batch, ~8s):

```
Scenario 1: Verify rejects bad candidate   → regression: avg dropped 1.000 -> 0.000 (p=0.0000), rejected
Scenario 2: Release gate rejects          → release regression gate: avg dropped 1.000 -> 0.000, rejected
Scenario 3: good candidate released        → verified → promoted
```
