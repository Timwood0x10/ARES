# ARES v0.3.0 发布说明

**发布日期：** 2026-08-11
**分支：** dev
**主题：** 候选发布闭环（Candidate Release Closed-Loop）

---

## 概述

v0.3.0 把进化系统的"选择"从"评估"升级为**分层发布门禁**：进化产出的策略被封装成有状态、可验证、可发布的**候选（Candidate）**，通过 `CandidatePipeline` 走"三层验证 → Release 发布门禁 → 发布前门3回归再确认 → SetStable"的完整生命周期。门3 用真实 LLM（`LLMArenaScorer`）做保留案例回归，`BatchScorer` 把对 LLM 的请求合并成大的以应对低 rpm 限流。

核心理念：**候选生成容易，上线难——发布这道门禁决定进化系统的安全性。** 一个候选必须证明自己在保留案例上不退化，才允许进入稳定区。

---

## 新功能

### 1. 候选管道（`internal/evolution/`）

```
NewCandidate → Verify（门1 静态 + 门2 证据 + 门3 回归）→ Verified
             → Release（coordinator 决策 + canary）→ 发布前门3再确认 → SetStable → Promoted
```

- **`Candidate` + `CandidateStore`**（`candidate.go`）：有状态候选对象，生命周期 `candidate → verified → promoted/rejected`；`CandidateStore` 并发安全（`sync.RWMutex`）。
- **`CandidateVerifier`**：三层验证——门1 静态（结构 + 危险模式拒绝）、门2 证据（引用失败 Evidence 真实存在且 `KindDimensionEval`）、门3 回归（保留案例不退化）。
- **`CandidatePipeline`**（`candidate_pipeline.go`）：`Release` 只接受 `StatusVerified` 候选，走 coordinator 决策 → canary → `SetStable` → `Promote`。
- **Release 门3**（`WithReleaseRegressionCheck`）：在**任何 patch 构建/应用之前**运行门3，失败则 `Reject` 且不触碰 runtime/stable。
- **死代码清理**：删除旧 `promoteToStable`/`applyDiff`（被 `CandidatePipeline.Release` 取代），消除双发布路径。

### 2. 门3 LLM 回归

- **`CandidateRegressionChecker`**（`candidate_regression.go`）：用 `ares_arena.RegressionTester` 对比 `stable.Instructions` vs `candidate.Diff`，统计显著变差（`Confident && NewAvg<OldAvg`）则拒绝。
- **`LLMArenaScorer`**（`internal/ares_evolution/service/llm_arena_scorer.go`）：实现 `ares_arena.Scorer`，两步调 LLM（执行 指令×案例 → 评分 [0,1]）。评分 prompt 保持开放式（锚点 rubric 实测削弱显著性）。
- **`BuildRegressionGate3` / `LoadRegressionGate3`**（`gate3_orchestrator.go`）：顶层装配，同一 check 可注入 Verify 和 Release 双层防线；`LoadRegressionGate3` 从 YAML 加载 `llm.Client`，支持 ollama（无 key）/ openai（有 key）。

### 3. 批量请求合并（`BatchScorer`）

- **`ares_arena.BatchScorer`**（`regression.go`）：可选接口 `ScoreBatch(ctx, strategy, count, testCases)`；`RegressionTester.runStrategy` 检测到则**一次批量调用算完所有 runs**（否则回退逐个并发 `Score`，向后兼容）。
- **`LLMArenaScorer.ScoreBatch`**：count 个执行 + 评分合并成 **2 次 LLM 调用**。一次回归从 `2×runs` 降到 2 次——对低 rpm provider 至关重要。

### 4. 可靠性加固

- `CandidateStore` 全 `sync.RWMutex`；`TestCandidateStore_ConcurrentAccess`（32 协程 × 50 提交）`go test -race` 通过。
- 门2 `replayFailureCases` 查询 evidence store，区分"缺失"与"kind 错误"，杜绝凭空 ID。
- `Verify()` 推进状态机：全关通过 → `StatusVerified`；任一失败 → `StatusRejected` + 原因；nil candidate 防护。

## Breaking Changes

| 变更 | 之前 | 之后 |
|------|------|------|
| `CandidateStore.promoteToStable` / `applyDiff` | 候选直达稳定区 | **删除**（用 `CandidatePipeline.Release`）|
| `CandidateVerifier` 构造 | `NewCandidateVerifier(regressionCheck)` | + `NewCandidateVerifierWithOptions(WithEvidenceStore, WithRegressionCheck)`（旧构造兼容）|
| `CandidatePipeline` 构造 | `NewCandidatePipeline(...)` | + `NewCandidatePipelineWithOptions(..., opts...)`（旧构造兼容）|

## 真实 LLM 实测（provider 对比）

同套保留案例：

| Provider | 模型 | 好策略 avg | 坏策略 avg | 判定 |
|----------|------|-----------|-----------|------|
| sensenova | deepseek-v4-flash | 0.85（单次） | 0.00 | rpm 极低，仅单次 |
| Ollama | gemma4:e2b | 0.20 | 0.00 | 执行弱，无法显著判定 |
| Ollama | gemma4:e4b | 0.16 | 0.03 | p=0.0051 显著 |
| **agnes-ai** | **agnes-2.5-flash** | **0.45** | **0.14** | **p=0.0297 显著 + 无 rpm** |

完整发布闭环（`examples/18-release-closed-loop`，agnes 批量，~8s）：

```
场景1: Verify 拒绝坏候选   → regression: avg dropped 1.000 -> 0.000 (p=0.0000), rejected
场景2: Release 门禁拒绝    → release regression gate: avg dropped 1.000 -> 0.000, rejected
场景3: 好候选发布成功       → verified → promoted
```
