## 🎯 修正后的 v0.3.0 建议方向

既然核心 Runtime 已完成，建议聚焦于**高级特性**：

---

### 方向一：多 Agent 协作模式（P2）

ares-runtime.md §10 说"不提前设计分布式 Scheduler"，但**协作模式**是另一回事：

#### 1.1 委托模式（Delegation Pattern）
```go
// internal/agentipc/collaboration.go
func (b *Bus) DelegateToSpecialist(ctx context.Context, 
    delegator, specialist string, taskID string, 
    specialization string) error {
    
    // 1. Delegator 发送委托请求给 Specialist
    // 2. Specialist acquire taskID（如果具备 specialization 能力）
    // 3. Specialist 执行后 Reply 结果
    // 4. Delegator 聚合结果
}
```

**使用场景**: Leader Agent 擅长规划但不擅长代码执行，委托给 code_agent

---

#### 1.2 流水线模式（Pipeline Pattern）
```go
func (b *Bus) CreatePipeline(ctx context.Context,
    stages []string, taskID string) (*Pipeline, error) {
    
    // A → B → C 流水线
    // 每阶段独立 Agent，数据通过 IPC 传递
    // 支持并行Stage（如果无依赖）
}
```

**使用场景**: 文档生成流程（research → write → review）

---

#### 1.3 编排模式（Orchestration Pattern）
```go
func (b *Bus) Orchestrate(ctx context.Context,
    coordinator string, workers []string,
    taskID string) error {
    
    // Coordinator 协调多个 Worker 并行执行
    // 聚合结果，处理失败重试
}
```

**使用场景**: 并行代码审查（多个 reviewer 同时工作）

---

### 方向二：Evolution-Runtime 深度集成（P2）

当前进化主要影响策略参数，可以扩展：

#### 2.1 进化影响的 Spawn 决策
```go
type EvolutionAwareSpawner struct {
    baseSpawner *agentfabric.Fabric

func (s *EvolutionAwareSpawner) Spawn(ctx context.Context, spec SpawnSpec) (*Agent, error) {
```

**进化维度**:
- Spawn 时机（何时 spawn 新 Agent）
- Spawn 数量（并行度优化）
- Capability 选择（选择什么类型的 Agent）

## 🎬 User Story 示例

```gherkin
作为 Ares 开发者，
我想要通过统一的 Kernel 编排多个 Agent 协作完成任务，
这样我就能实现复杂的多步任务，而不只是单 Agent 执行。

验收标准：
- [ ] Leader Agent 可以将子任务委托给 Specialist Agent
- [ ] Specialist Agent 执行后返回结果给 Leader
- [ ] Leader 可以聚合多个 Specialist 的结果
- [ ] 支持流水线模式（A → B → C）
- [ ] 支持编排模式（Coordinator 协调多个 Worker）
```

## 结论

ares-runtime.md 的核心设计（Task Fabric + Agent Fabric + IPC + Kernel）**已经完成**。

v0.3.0 应该聚焦于**高级特性**：
1. **多 Agent 协作模式** - 兑现"同级认知进程"的设计愿景
2. **Evolution-Runtime 深度集成** - 让进化影响更多维度
3. **可解释性与人工反馈** - 提升用户信任
4. **全局观测与调试** - 提升运维效率

这些功能的完成将真正释放 ares-runtime.md 的设计潜力。
